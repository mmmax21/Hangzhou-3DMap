## 阶段 2：地理数据（Opus，2026-11-11）

### 做了什么

- `pipeline/fetch.sh` 下载 Copernicus GLO-30 瓦片（N30 E120）和 OSM（Overpass，查询在 `pipeline/osm-query.overpass`），存到 `pipeline/cache/`，这个目录不入库。
- `pipeline/build_data.py` 生成 `app/public/data/` 下的文件：
  - `heightmap.png`：1024×1024，16 位。最低最高海拔和水位写在 `heightmap.json`（6.0 到 396.9 米，西湖水位 7.5 米）。DSM 里的楼宇已抹平：平原用 9×9 灰度开运算，山区用 3×3，两者按高程过渡。湖区用遮罩压平到水位以下 1.5 米。
  - `water.geojson` 和 `watermask.png`：三个通道分别是 R 遮罩、G 水内离岸距离、B 陆上离水距离。
  - `buildings.json`：9849 栋参与渲染，原始 10914 栋。96% 没有高度和层数，按 12 米处理。
  - `roads.json`：trunk、primary、secondary、tertiary 四级道路，隧道已去掉。
- 10 个景点按 OSM 校准，坐标回写到 PRD 第 4 节，生成 `app/src/data/landmarks.json`，其中 `poem` 和 `intro` 留空。**原表的坐标其实是 GCJ-02**，和 WGS-84 差约 450 米。
- 验收图在 `docs/verify/water-overlay.jpg`：把水岸线和景点叠在 Esri 卫星图上，偏差只有几米。

## 阶段 3：渲染骨架（Opus，2026-11-11）

### 做了什么

- `app/`：Vite、React、TS、three 0.169、r3f 8、drei 9、postprocessing、GSAP、zustand。`npm run dev` 启动后打开 http://localhost:5173。
- **坐标**：`src/geo/geo.ts` 的 `lngLatToScene` 是唯一的经纬度转换函数。地表高度用 `src/scene/terrainHeight.ts` 的 `terrainY`，已经包含 2 倍夸张和八边形边缘压低。
- **昼夜**：`src/state/night.ts` 里的 `uNight` 是唯一的昼夜状态。所有着色器共用同一个 uniform 对象，GSAP 补间 3 秒。颜色在 GLSL 里写成 `vec3 x[2]`，用 `DNC(x)` 插值。
- **地形**（`Terrain.tsx`）：在 CPU 上按高度图位移网格，512 段，约 48 万面。片元着色器从浮点高度图逐像素算法线和凸度：
  - 石青放在高处、山脊和陡坡，石绿在山谷，赭黄在山麓，平原和湖岸绿带另有颜色。
  - 笔触是沿等高线方向扭曲的横向噪声。没有用贴图，`brushScale`、`brushContour` 两个参数可调。
  - 金线是平滑凸度场的等值线，再叠一层很淡的凸处等高线。夜晚颜色会乘一个系数后进入辉光。
- **水面**（`Water.tsx`）：独立平面，用遮罩丢弃水外像素。白天近似纯色，近岸略带倒影色。夜晚有月光倒影带，月亮方向每帧同步；岸边还有沿视线拉长的暖色条纹。
- **建筑**（`Buildings.tsx`）：合并成一个网格，约 15.8 万面，景点周围 12 个单位内不放。墙和顶按法线着色，高楼降低饱和度。夜晚用程序化窗格发光，远处退化为平均亮度以免闪烁。
- **夜晚灯光**（`NightLights.tsx`）：道路白天是浅色小路，夜晚变成暖色灯带。湖岸灯点是 942 个点精灵，只在夜晚显示。
- **底座**（`Base.tsx`）：程序化的八边形厚板，顶边有金线。正面铭牌用 canvas 生成，包括「杭州西湖」、WEST LAKE · HANGZHOU 和朱红印章，颜色随昼夜变化。
- **相机**（`CameraRig.tsx`）：OrbitControls。俯仰角限制在 20° 到 75°，有缩放上下限，目标点限制在沙盘内。静止 10 秒后缓慢环绕，URL 加 `?noauto` 可以关闭。
- **后期**（`PostFX.tsx`、`PaperEffect.ts`）：辉光、移轴、暗角、宣纸纹理。宣纸纹理只在白天出现，所有强度都随 `uNight` 插值。
- **月亮**（`Atmosphere.tsx`）：固定在画面右上方，作为背景，只在夜晚出现。three.js 的半球光和方向光也随昼夜插值，给阶段 6 的 GLB 模型用。
- **景点**：占位方块放在校准后的坐标上。白堤和苏堤用扁圆柱表示。
- **可调参数**全部在 `src/config/style.ts`。PRD 第 2.2 节里调整过的色值已经回写。

### 完成标准自查（PRD 第 8 节）

2. 西湖、苏堤、白堤、三个岛都能认出来：湖岸有绿带勾边，堤和岛是绿色细带。✅ 全景下苏堤偏细，拉近更清楚。
3. 白天对比图：`docs/screenshots/compare-day.jpg`。配色关系对得上：暖米色背景和底座、米色湖面、青绿山体加金线、白墙灰顶。⚠️ 差距见下文。
4. 夜晚对比图：`docs/screenshots/compare-night.jpg`。暗蓝背景、深蓝湖面、月亮和月光倒影带、湖岸暖色灯点、底座金边都有了。⚠️ 差距见下文。

   - 1920×1080：每帧中位 6.4 毫秒，最快 4 毫秒，折合约 150 帧。
   - 2880×1620，也就是像素比 1.5：约 10.5 毫秒。
   - 按 M1 的 GPU 慢 4 到 5 倍估算，1080p 下约 25 到 30 毫秒，**达不到 60 帧**。需要在画质分档阶段处理。

### 与定稿图仍有差距的地方

- **山不够高、不够陡**。PRD 规定 2 倍夸张，真实地形下山体相对整块沙盘很平，定稿图的山更高耸、轮廓更戏剧化。这是最大的观感差距。要改就把 `terrain.exaggeration` 调到 3 到 4，同时先改 PRD 第 3 节。
- **构图不同**。真实比例下西湖只占沙盘中间约四分之一，东边城区占了大片面积；定稿图里湖几乎铺满沙盘。这一点 PRD 说不比较，但会影响氛围。可以考虑把城区建筑的透明度或密度做淡。
- **没有树、云雾、景点模型**，属于阶段 6。定稿图的「精致感」大部分来自这些元素，尤其是柳树环湖和山腰云雾。
- **笔触是程序噪声**，没有绢本的质感。图像模型产出笔触贴图后，可以在地形着色器里叠加。
- **夜晚城区**：道路灯带比窗灯显眼。窗格在远处退化成均匀的暖褐色，没有定稿图那种点点灯火的感觉。
- **夜晚金线**：还偏像等高线圈，定稿图是沿主山脊的长线。如果要真正的山脊线，可以在管线里做流域分析，算出山脊网络，烘焙进一张贴图。

### 给 Astra 的提示

- **截图和测速**（开发环境专用）：
  - `window.__shot('name')` 会同步渲染一帧，把画布存成 `docs/screenshots/name.png`，这个接口由 `vite.config.ts` 的中间件提供。
  - `window.__night(true|false, instant)` 切换昼夜。
  - `window.__controls` 是 OrbitControls 实例。
  - `window.__advanceOnce()` 渲染一帧，可以配合 timer query 测 GPU 耗时。
  - URL 加 `?stats` 会在左上角显示帧率、绘制调用和三角面数。
- 内置浏览器面板在后台时 rAF 会被节流到 1 帧/秒左右，页面加载要等很久。所以测性能要用 timer query，不要看 rAF 帧率。
- **性能**：大头是地形片元着色器（9 次高度采样和若干噪声）和 4K 下的 MSAA 加后期。画质分档时：
  - 低档：MSAA 0 到 2，关掉移轴和宣纸纹理，像素比 1。
  - 地形网格段数可以降到 256。
  - 像素比上限目前是 1.5（`style.render.maxDpr`），PRD 允许最高 2。
- **接入景点 GLB**：每个景点放在 `lngLatToScene` 加 `terrainY` 算出的位置。把 `Landmarks.tsx` 的占位方块换掉即可。夜晚自发光强度从 `uNight.value` 插值。
- **地形调色**：地形色带的阈值依据是高度图凸度的分布，90 分位约 0.008。参数是 `ridgeBlue` 和 `ridge.convexity`，改的时候参考这个分布。
- **默认机位**在 `style.camera`。对比截图用的是 1448×1086 视口和默认机位。

## 阶段 3 返工（Opus，2026-11-11）

视觉总监同意返工，原因是 PRD 原定范围太大、2 倍夸张太小，对比图离定稿图太远。PRD 已先行修改（第 3 节、6.3 节、6.4 节）。

### 改了什么

- **范围**：缩小为经度 120.100 到 120.168、纬度 30.215 到 30.270，约 6.5 公里乘 6.1 公里。
  - 湖宽约占沙盘一半，东岸只留约 800 米的城区。
  - 西边仍包含北高峰一带，南边包含雷峰塔后面的南屏山和玉皇山。
  - 10 个景点都在范围内，离边界最近的是保俶塔，约 750 米。
  - 管线已按新范围重跑。建筑从 9849 栋减到约 5300 栋，道路从 1656 段减到 539 段。
- **夸张**：3.5 倍，高处另加一条曲线：海拔差达到 240 米时再乘 1.2。参数是 `terrain.exaggeration`、`peakCurve`、`peakRef`。
  - JS 的 `elevationToY` 和 GLSL 的 `terrainYm` 共用这一套公式，法线也按夸张后的高度计算。
  - 试过把曲线系数设为 0.5，山顶会变成尖刺，所以收回到 0.2。
- **石青**：现在主要由相对高度决定，凸度和笔触只做小幅扰动。山的上半部成片偏青，不再是零散斑点。
- **金线**：改为管线烘焙的山脊网络 `ridges.png`，算法是反转地形的汇流累积，详见 `pipeline/README.md`。
  - 着色器采样距离场，按屏幕像素画线，弱支脉淡出，参数是 `ridge.minStrength`。
  - 原来的凸度等值线和等高线已删除。
- **机位和底座**：默认机位压低，俯角约 37°，能看到山的侧面轮廓。底座厚度从 62 加到 82，铭牌按新尺寸调整。
- **夜景**：
  - 道路只保留 trunk、primary 两级和离湖约 90 米以内的环湖路，夜晚亮度调低一档。
  - 月光倒影改为按角宽度计算的窄带：从相机朝月亮方位延伸，再切成横向碎光。
  - 窗灯改为 LOD 窗格：远处按 2 的幂合并窗格，每个亮点至少约 2.5 像素，形成点点灯火的颗粒感。
- 新的对比图：`docs/screenshots/compare-day.jpg`、`compare-night.jpg`。

### 数据

- 场景约 52.6 万面，36 次绘制调用。
- 1080p（1920×1080 缓冲区）GPU 每帧中位 5.1 毫秒，最快 3.6 毫秒，测试机是 M3 Max。按 M1 估算约 20 到 25 毫秒，仍未必到 60 帧，需要在画质分档时处理。

### 仍有差距

- 没有树和云雾。定稿图里山腰云雾和环湖柳树是氛围的主要来源，现在山脚和平原显得空。
- 定稿图的山轮廓圆润、层层叠叠；真实 DEM 的山脊更碎，个别山峰在 3.5 倍下仍偏尖。
- 湖西的茅家埠、杭州花圃一带是大片低平地，画面上是一片绿和米色，层次少。
- 夜晚城区灯火比定稿图稀疏，湖面上缺少船只和景点的暖色倒影，这些要等景点模型接入。
- 白天金线偏淡。定稿图的金线更醒目，可以调 `ridge.strength.day` 和 `width`。

## 主镜头重构，第二轮（Fable，2026-11-11）

第一轮的方向得到确认，这一轮加开场、入夜过程、动效和明暗。

### 改了什么

- **开场**（`style.entrance`、`Scene.tsx`、`CameraRig.tsx`、`PaperEffect.ts`、`state/intro.ts`）：先是高处俯视的一幅平铺水墨，随后山隆起、颜色晕开、镜头降到主镜头，全程约 6 秒。水墨效果是后期里的一个 `ink` 参数。用户一拖动就中止运镜。
- **入夜灯火依次点亮**（`shaders/common.ts` 的 `lightsOn`）：岸灯、窗灯、水中灯影、景点、游船、孔明灯都按从东到西的先后点亮。昼夜过渡时长从 3 秒延到 5.5 秒。
- **孔明灯**（新增 `SkyLanterns.tsx`、`style.skyLanterns`）：80 盏，夜晚从湖面一带循环升起。
- **游船**（新增 `Boats.tsx`、`style.boats`）：6 艘画舫沿水面上的圆形航线行驶，航线自动避开岸和岛，夜晚船舱亮灯。
- **明暗**：树冠下暗上亮；景点脚下加接触阴影；地形的环境光调低、主光调高。

### 验证

- PRD 第 2.2 节的水色、第 3 节的夸张倍数、第 5 节的开场和昼夜过渡时长还没有同步。
- 低画质档、手机、帧率都没有重新检查。孔明灯和游船在低画质档没有关闭。
- 没做：山体笔触质感、真实投影、柳枝摆动、飞鸟、落花。

视觉总监反馈：景点悬停时不要跳起；湖水不够真实。

- **湖水**（重写 `Water.tsx`，参数在 `style.water`）：
  - 高画质用 three.js 的 `Reflector` 渲染真实倒影，山、塔、树、灯火都会映在水里。倒影按波纹扰动，并沿竖直方向拉长。

  - 波纹改为两层不同方向和速度的噪声，近岸更平静。
  - 白天加了太阳在波纹上的波光。
  - 原来的假灯影在有真实倒影时减弱到 45%。月光带保留。
  - 低画质档不渲染倒影，用原来的简化水面。

### 验证

`npx tsc -b` 和 `npm run build` 通过。浏览器高画质下看过主镜头的白天和夜晚，截图是 `docs/screenshots/r3-water-day.jpg`、`r3-water-night.jpg`。截图之后又把白天波纹从 0.07 调到 0.05、`reflectBase` 从 0.14 调到 0.2，这两个数值没有再截图确认。

### 没做 / 已知问题

- 倒影让场景每帧多渲染一遍，帧率没有测量。
- 低画质档的简化水面没有实际看过。
- 窗口尺寸变化时会重建倒影贴图，拖动窗口边缘时可能有一瞬卡顿。

## 第四轮：画卷导览（Fable，2026-11-12）

给作品一条叙事线：镜头自动依次飞过七站，每站浮现竖排的景名和诗句，光线和天气随之变化，全程约 69 秒。

### 改了什么

- **脚本**（新增 `data/tour.ts`）：七站是西湖全景、苏堤春晓、曲院风荷、雷峰夕照、三潭印月、断桥残雪、收尾全景。每站有景名、两句诗、出处、昼夜值、天气、镜头起止偏移。
- **导演**（新增 `scene/TourDirector.tsx`、`state/tour.ts`，参数在 `style.tour`）：一条 GSAP 时间线驱动相机、昼夜、天气和文字。开场结束 2.5 秒后，如果用户没动过画面就自动开始；拖动画面或点景点立即停止；右上角有「导览 / 停止」按钮。URL 带 `?noauto` 时不自动开始。
- **昼夜中间值**（`state/night.ts` 的 `level`）：雷峰夕照用 0.42 的黄昏，断桥残雪用 0.15 的阴天。
- **天气**（新增 `scene/Weather.tsx`、`state/weather.ts`、`style.weather`）：雪和落花共用一套粒子，范围跟随镜头注视点。
- **界面**（新增 `ui/Tour.tsx`，样式在 `index.css` 末尾）：竖排楷体景名、诗句、出处和一枚朱印。导览期间隐藏景点列表。
- **相机**：最小距离从 100 降到 40，最小俯仰角从 9 度降到 4 度，近景才能平视并把远山收进画面。
- **修了一个缺陷**：开场运镜的动画在组件卸载时没有停掉。开发模式下 React 会把它创建两次，多出的那个停不下来，一直和导览抢镜头。现在卸载时会停掉，导览开始时也会让开场运镜和景点飞行让位。

### 验证

`npx tsc -b` 和 `npm run build` 通过。浏览器高画质、1280×720 下用 `window.__tourTl`（开发环境）逐站定格查看了苏堤、曲院、雷峰、三潭、断桥五站，截图是 `docs/screenshots/tour-*.jpg`。

### 没做 / 已知问题

- **诗句需要人工核对。** 六处引文的作者和篇名是凭记忆写的，尤其是尹廷高《雷峰夕照》和张祜《题杭州孤山寺》两处。
- 预览面板帧率被节流，只看了定格画面，没有看过连贯播放。飞行和停留的时长、诗句出现的时机可能要调。
- 两个全景站和自动开始的逻辑没有实际看过。
- 曲院风荷这一站没有荷花，荷叶实例化一直没做。
- 诗句压在树丛等杂乱背景上时可读性一般，可能需要加底衬。
- 手机上的竖排排版和低画质档没有检查。
- 导览不改季节的地表颜色，断桥残雪只有飘雪，地面没有积雪。

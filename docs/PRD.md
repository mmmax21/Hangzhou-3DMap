# 杭州西湖 3D 景点沙盘 · PRD 与风格规范

版本 1.0 · 2026-11-11 · 工期 1 到 2 天

本文档是所有参与模型的唯一依据。与本文档冲突的做法，先改文档再动手。

---

## 1. 产品定义

一个公开访问的网页。打开后看到一块青绿山水风格的西湖沙盘，可以旋转缩放，点击景点后相机飞过去并显示介绍，可以在白天和夜晚之间切换。

- **用途**：个人作品展示。
- **受众**：桌面浏览器用户。手机可以打开，画质降档。
- **语言**：仅中文。
- **声音**：无。

### 首版包含

1. 真实地理数据生成的西湖核心区地形、水面、建筑体块。
2. 10 个可点击的景点精模。
3. 昼夜两个场景及其平滑过渡。
4. 自由视角相机和景点飞行。
5. 入场动画。
6. 高、低两档画质。

### 首版不包含

四季切换、西湖十景逐景场景、钱江新城、声音、多语言、后台管理、用户账号。

## 2. 风格规范

定稿图在 `定稿图4选1/`：**图2 是白天，图4 是夜晚**。两者共用同一套造型，只换光和色。

### 2.1 造型规则

| 元素 | 规则 |
|---|---|
| 沙盘 | 一块有厚度的八边形切角底座，四周留边，放在纯色背景上 |
| 山 | 平滑起伏，不要低多边形的硬棱。山脊有金色细线 |
| 水 | 平静，接近纯色。白天几乎无波纹，夜晚有月光倒影带 |
| 云雾 | 贴着山腰的薄雾带，不遮挡湖面和景点 |
| 普通建筑 | 按真实轮廓挤出的简单体块。白墙、深灰顶。高楼降低饱和度和对比度，不抢山水 |
| 树 | 风格化的团状树冠，柳树为下垂的黄绿色团。使用实例化，不逐棵建模 |
| 景点 | 比真实比例放大 2 到 3 倍，是画面中细节最高的物体 |
| 底座铭牌 | 正面居中「杭州西湖」，配小字 WEST LAKE · HANGZHOU 和一枚朱红印章 |

## 3. 场景范围与坐标约定

- **范围**（WGS-84）：经度 120.100 到 120.168，纬度 30.215 到 30.270。约 6.5 公里乘 6.1 公里。湖宽约占沙盘一半，西含北高峰，南含雷峰塔后的南屏山、玉皇山，东岸只留约 800 米的湖滨城区。（阶段 3 返工时由原 9.6×8.9 公里缩小，原范围下湖只占画面四分之一。）
- **坐标系**：所有数据统一为 WGS-84。来自高德或百度的坐标必须先从 GCJ-02 或 BD-09 转换。
- **场景单位**：1 单位等于 10 米。原点在范围中心，X 轴向东，Z 轴向南，Y 轴向上。
- **地形垂直夸张**：3.5 倍，并对高处做非线性加陡（参数 `terrain.exaggeration`、`terrain.peakCurve`，公式见 `app/src/scene/terrainHeight.ts`）。只作用于地形，不作用于建筑和景点。（阶段 3 返工时由 2 倍提高，2 倍下山体过平，读不出「三面云山」。）
- 经纬度到场景坐标的转换只允许写在一个函数里，全项目共用。

### 景点卡片内容

每个景点一条数据，放在 `app/src/data/landmarks.json`：

```json
{ "id": "leifeng", "name": "雷峰塔", "lat": 30.2316, "lng": 120.1489,
  "poem": "", "poemSource": "", "intro": "", "model": "leifeng.glb" }
```

- `poem`：一句古诗，必须是真实存在的诗句，注明作者和篇名。**不允许模型自己编写诗句**，拿不准就留空。
- `intro`：100 字以内。

## 5. 交互

| 操作 | 行为 |
|---|---|
| 打开页面 | 入场动画：底座淡入，地形从平面隆起，建筑和景点依次升起，约 3 秒。之后相机缓慢自动环绕 |
| 拖拽 | 旋转视角。限制俯仰角在 20 到 75 度，不能钻到地面以下 |
| 滚轮或双指 | 缩放，有最近和最远限制 |
| 悬停景点 | 景点轻微上浮并显示名称 |
| 点击景点 | 相机用 1.5 秒飞到该景点的预设机位，显示卡片 |
| 关闭卡片或点击空白 | 相机回到全景 |
| 昼夜开关 | 右上角一个按钮。过渡时长 3 秒 |
| 用户操作后 | 停止自动环绕，静止 10 秒后恢复 |

界面元素只有：昼夜开关、景点卡片、左下角景点列表（可折叠）。界面配色跟随昼夜变化，字体用宋体类衬线字体。

## 6. 技术方案

### 6.1 技术栈

Vite、React、TypeScript、three.js、@react-three/fiber、@react-three/drei、@react-three/postprocessing、GSAP（相机动画）、zustand（状态）。渲染器用 WebGL 2。

### 6.2 目录

```
docs/PRD.md              本文档
docs/PROGRESS.md         交接日志，见第 9 节
pipeline/                地理数据处理脚本
app/                     网页项目
app/public/data/         高度图、水系、建筑数据
app/public/models/       清理后的景点 GLB
assets-raw/              图像模型和 Tripo 的原始输出，不进入网页
```

文件夹里已有的 `web/`、`scripts/`、`data/` 等旧内容不在本方案范围内，新代码不依赖它们。

### 6.3 地理数据管线

| 数据 | 来源 | 输出 |
|---|---|---|
| 地形 | Copernicus GLO-30 DEM | `heightmap.png`，1024 乘 1024，16 位灰度，另附最低和最高海拔 |
| 水系 | OSM `natural=water` | `water.geojson`，用于生成水面遮罩 `watermask.png` |
| 建筑 | OSM `building=*` | `buildings.json`，只保留轮廓和高度。缺高度的按层数乘 3 米，都没有的给 12 米 |
| 道路 | OSM 主要道路 | `roads.json`，只用于夜晚的灯带，可选 |
| 山脊 | 由高度图做流域分析（反转地形的汇流累积）提取主山脊 | `ridges.png`，1024 乘 1024：R 为到最近山脊的距离场，G 为该山脊的强度 |

验收：把水系轮廓和景点坐标叠在卫星图上，偏差不超过 30 米。

DEM 在湖面上有噪声，生成地形时用水面遮罩把湖区压平到统一水位。

### 6.4 核心渲染设计

**一个全局参数 `uNight`（0 到 1）驱动所有昼夜变化。** 配色、光照、雾色、金线发光强度、窗灯、辉光强度都从它插值。不允许任何模块自己维护昼夜状态。

| 模块 | 做法 |
|---|---|
| 地形 | 高度图位移的平面网格。片元着色器按高度和坡度混合石青、石绿、赭黄三色，叠加一张笔触纹理 |
| 山脊金线 | 采样 `ridges.png` 的距离场画沿主山脊的长线，只保留主要山脊，宁少勿多。夜晚输出为发光 |
| 水面 | 独立平面。白天纯色加极轻微的法线扰动；夜晚加月光倒影带和岸边灯光的拉长倒影 |
| 建筑 | 合并为单个网格。墙和顶按法线方向着色。夜晚用程序化的窗格图案发光 |
| 树 | 两到三种树冠网格，实例化渲染，位置按 OSM 绿地和堤岸线撒点 |
| 云雾 | 若干朝向相机的半透明噪声面片，缓慢漂移 |
| 景点 | GLB 模型。夜晚统一加暖色自发光和一个辉光光点，不需要单独的发光贴图 |
| 底座 | 程序化生成的八边形厚板，铭牌用贴图 |

### 6.5 性能预算

| 项 | 高画质 | 低画质 |
|---|---|---|
| 目标 | 1080p 下 60 帧（M1 级别集成显卡） | 手机 30 帧 |
| 总三角面 | 150 万以内 | 50 万以内 |
| 绘制调用 | 150 以内 | 80 以内 |
| 后期 | 全开 | 只留辉光和色调 |
| 云雾、树 | 全量 | 云雾关闭，树减半 |
| 像素比 | 最高 2 | 固定 1 |

首屏加载总量 15MB 以内。启动时根据设备自动选档，界面不提供手动切换。

## 7. 资产规范

### 7.1 参考图（图像模型）

每个景点一张，用于输入 Tripo。提示词模板，替换方括号内容：

```text
A single [建筑的英文描述, e.g. five-story octagonal Chinese pagoda with a golden spire], isolated on a plain white background, three-quarter view from slightly above, entire object visible with margin. Stylized 3D model in the style of a hand-painted miniature: off-white plaster walls, dark gray tiled roofs with upturned eaves, dark red-brown wooden columns, thin gold trim. Smooth simplified forms, matte materials, flat even lighting with no cast shadows and no strong highlights, no ground, no trees, no people, no text.
```

要求：所有景点用同一套提示词骨架，一次性生成后并排检查风格是否一致，不一致的重新生成。

另需生成两张贴图：

```text
Seamless tileable texture of mineral pigment brushstrokes on silk, in the style of Song dynasty blue-green landscape painting, fine parallel hemp-fiber texture strokes, subtle variation, neutral gray tones only, flat lighting, top-down, no objects.
```

```text
Seamless tileable texture of aged rice paper, warm ivory, very subtle fibers, flat even lighting, no objects, no text.
```

### 7.2 模型（Tripo）

| 项 | 要求 |
|---|---|
| 格式 | GLB，带 PBR 贴图 |
| 朝向 | Y 轴向上，正面朝 Z 轴正方向，底部中心在原点 |
| 光影 | 贴图中不能有烘焙的阴影和高光。有的话重新生成或在清理时压平 |
| 原始文件 | 存入 `assets-raw/tripo/`，不直接用于网页 |

### 7.3 清理后的交付标准

用 gltf-transform 脚本批量处理，个别需要在 Blender 手修。

| 项 | 标准 |
|---|---|
| 三角面 | 每个 3 万以内，塔类可到 4 万 |
| 贴图 | 1024 乘 1024，WebP |
| 压缩 | Meshopt |
| 体积 | 每个 1.5MB 以内 |
| 命名 | 与 `landmarks.json` 的 `id` 一致，如 `leifeng.glb` |

### 阶段 3 的完成标准

1. `npm run dev` 能启动，无控制台报错。
2. 西湖的形状、苏堤、白堤、三个岛清晰可辨。
3. 白天截图与图2 并排，配色和氛围接近。
4. 夜晚截图与图4 并排，配色和氛围接近。
5. 昼夜切换平滑，无闪烁。
6. 目标设备上达到 60 帧。

### 工期紧张时的削减顺序

按顺序砍，砍到能按时完成为止：

1. 景点从 10 个减到 5 个：雷峰塔、断桥、三潭印月、保俶塔、湖心亭。
2. 去掉云雾。
3. 去掉入场动画。
4. 建筑夜晚不做窗灯，只做整体微光。
5. 手机端只显示一张静态图和「请用电脑访问」的提示。

昼夜过渡、水面、山体着色不能砍，它们是这个项目的核心。

## 9. 协作规则

1. 所有模型在同一个仓库工作。开工前先读本文档和 `docs/PROGRESS.md`。
2. 每个阶段结束时在 `docs/PROGRESS.md` 追加一段：做了什么、没做什么、已知问题、下一个接手者需要知道的事。
3. 色值、性能预算、坐标约定如有调整，先改本文档。
4. 所有可调的视觉参数集中在 `app/src/config/style.ts`，不要散落在各个着色器里。迭代阶段主要改这一个文件。
5. 每个阶段单独提交，提交信息写明阶段编号。
6. 不提交 `assets-raw/` 中的大文件和 `node_modules`。
